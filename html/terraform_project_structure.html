1. Terraform Project Structure

At work we were given recipes for various projects as a directory of terraform modules. This can become unwieldy as the project grows.

I asked Gemini, set to Pro, to show me a better way and what it gave I think will work much better.

The project directory structure looks like this:

infrastructure/
├── modules/
│ ├── network/ # (Reusable VPC module)
│ └── database/ # (Reusable Cloud SQL module)
└── layers/
    ├── 00-bootstrap/ # Creates the State Bucket
    ├── 01-networking/ # Uses the bucket, builds VPC
    └── 02-database/ # Uses the bucket, builds DB in VPC

The modules are generic, reusable terraform blocks.

The layers is where the magic happens. 

# We configure this bucket to store all future Terraform states
resource "google_storage_bucket" "terraform_state" {
  name          = "my-company-tf-state-prod" # Must be globally unique
  location      = "US"
  force_destroy = false

  # Critical for Terraform state: If you mess up, you can revert to an older state!
  versioning {
    enabled = true
  }

  # Ensure state files are encrypted and not publicly accessible
  public_access_prevention = "enforced"
}

# Tell Terraform to store this layer's state in the centralized bucket
terraform {
  backend "gcs" {
    bucket  = "my-company-tf-state-prod"
    prefix  = "terraform/state/network"  # <-- This is the isolated folder
  }
}

# Call our reusable network module
module "base_network" {
  source       = "../../modules/network"
  network_name = "prod-vpc"
}

output "vpc_link" {
  value = module.base_network.network_self_link
}

# Use the SAME bucket, but a DIFFERENT prefix
terraform {
  backend "gcs" {
    bucket  = "my-company-tf-state-prod"
    prefix  = "terraform/state/database"  # <-- Isolated folder for DB state
  }
}

# 1. Look up the VPC created by Layer 01
data "google_compute_network" "my_network" {
  name = "prod-vpc"
}

# 2. Call the reusable database module
module "primary_db" {
  source = "../../modules/database"

  instance_name      = "prod-db-instance"
  region             = "us-central1"

  # Pass the network ID dynamically
  private_network_id = data.google_compute_network.my_network.id
}

Note: The state bucket is a common bucket for all the state layers but each layer's state resides in its own folder.

1.1. Workflow

  1. cd layers/00-bootstrap && terraform apply -> Creates the my-company-tf-state-prod bucket.
  2. cd layers/01-networking && terraform init && terraform apply -> Terraform connects to the bucket, creates the VPC, and saves the state to …/network/default.tfstate.
  3. cd layers/02-database && terraform init && terraform apply -> Terraform connects to the same bucket, queries GCP for the VPC name, builds the database, and saves the state to …/database/default.tfstate.
